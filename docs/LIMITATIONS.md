# Limitations

[DEVELOPMENT-STATUS.md](../DEVELOPMENT-STATUS.md) distinguishes implemented behavior and outstanding checks. The scoped local CLI/citation slice and fresh Windows wheel supplement are accepted with notes; whole-app acceptance remains pending. The partial `local-cli-mvp/1` profile explicitly defers MCP distribution; this does not waive any broader quality, provenance, safety or independent-review requirement. The CLI connects the canonical retained-row producer/resolver and required-reference assessment over the explicit source snapshot. Literal identity does not establish semantic truth.

The local deterministic flow is implemented and tested against hand fixtures. A provisional agent-authored source/Gold freeze exists. The S8 public config, raw matcher and canonical S2 adapter/local comparison/report components have separate new hand-toy conformance, including bounded bootstrap mechanics; they do not convert or evaluate the original corpus. Independently admitted original-corpus/heldout quality evaluation, numerical benchmark comparisons, live provider adapters/testing and finished-app acceptance remain incomplete. Canonical S2 generic evaluation and S3/S6 offline components are adopted with moved conformance. The explicit S8 Python annotation API and separate companion preserve deterministic core artifacts; normal CLI analysis keeps annotation disabled. No detection accuracy or real-network generalization is claimed. See [canonical evaluation scope](canonical-evaluation.md).

Inputs are Zeek conn TSV with declared headers or JSONL, not generic firewall logs. Maximum input200MiB, analyzed rows250000, physical line16KiB, rule buckets/groups10000 and complete output64MiB; caller limits can reduce these bounds. Partial/quarantined records and unknown fields/counters remain explicit. Above the hard input-byte cap there is no analyzed generation or invented row count. Full evidence support can exceed the output cap; the command fails instead of silently sampling evidence. The canonical connection additionally refuses more than 5,000 required physical rows and preserves every canonical overflow failure without a fake Pointer. Affected explanations/proposals become investigation-only. Per-group source rechecks prioritize integrity; large group sets can be slow and have not been benchmarked.

Parser profile `zeek-conn-1.1` retains positive `missed_bytes` and validated history `g/G` as `capture_loss`, and validated history `x/X` as `incomplete`. These are [Zeek capture/analysis signals](https://docs.zeek.org/en/current/scripts/base/protocols/conn/main.zeek.html#type-Conn::Info). A fully read file can have a complete physical parse while its rule channels/groups are partial; those groups produce investigation text without a proposed rule. Invalid ancillary history remains an event with `invalid_history`; it is not interpreted as a gap or silently dropped. Reports record the parser profile. Verification uses the installed producer and rejects an older producer's differing artifacts; it does not reproduce an obsolete parser.

Internal CIDRs and permitted destinations/services are explicit policy, not inferred from traffic. The default permitted peer/service lists are empty. Suppressions require bounded, active rule-specific contexts and remain in the audit. A suppressed backup-shaped transfer can hide encrypted exfiltration; slow/distributed scans can miss fixed windows. Large origin-byte totals and regular timing alone are not malicious-intent evidence. Missing byte values remain unknown, not zero.

Zeek connection state cannot prove literal firewall-policy denied-then-allowed changes. The separate rejected-then-established connection diagnostic does not satisfy that capability. Empty groups mean explanation coverage N/A, not100% or benign traffic; unsupported and not-evaluable channels remain explicit.

Reports contain complete raw supporting rows/base64 and endpoint data. HTML escapes data and has no script/remote dependency. Artifacts are not signed; verification recomputes using explicit caller source and recorded settings, and does not authenticate a policy choice or a human approval. A report is a snapshot, not an assertion that the source can never change later. A write failure can leave an incomplete directory without a manifest; existing directories are never overwritten.

The local CLI performs no firewall changes, cloud provisioning, model calls or publication. Domain EvidenceRefs support recomputed statistics, and the report path also resolves canonical S5 Event Pointers against retained physical rows. Unsupported citations retain their original required denominator and downgrade affected explanations/proposals. Literal row identity does not establish semantic truth. Provider response validity would not establish correctness or confidence calibration.

Optional offline annotation requires an explicit caller Provider/real Ledger/budget/context/limits/allocation and zero outbound quota. Only numeric/enum computed state reaches canonical S6 rules/preparation/wrapping and canonical S3 typed requests. Authored fixture hits remain mock, misses never dispatch, low/invalid/stale/held/unavailable results keep flags and proposals intact, fractional triage stays fractional and confidence0.6 is uncalibrated. Current lookup accounting and original source usage/cost/latency remain distinct; unknown source values stay null. Generated config/annotation.json is policy inventory, not runtime overrides.

The explicit offline companion composer requires the original ordered requested group frame and actual caller-prepared canonical accounting objects. It verifies/snapshots the original core and source around lookups, writes only a bounded new sibling bundle and retains every requested outcome/fallback. The original six core files remain unchanged. Companion hashes do not establish result authenticity, current provider state, calibration or model quality; `fwa verify` still verifies only the original deterministic core without a hidden lookup. No model-answer authenticity verifier or default CLI provider setup is provided. See offline-annotation.md.
